01 · Contexto

Por que prever a degradação de uma rede?

A latência, a variação de atraso (jitter) e a perda de pacotes ajudam a identificar mudanças na qualidade de uma conexão. Porém, o RTT absoluto não conta a história toda: rotas diferentes podem ter tempos de resposta naturalmente diferentes.

↗

O problema do valor absoluto

Um RTT alto pode ser normal para uma rota longa e anormal para uma rota curta. Usar um único limite fixo pode gerar alarmes inadequados quando as condições de referência variam.

≈

Baseline por rota

O projeto utiliza uma janela histórica de referência e medidas robustas — mediana e desvio absoluto mediano (MAD) — para caracterizar o comportamento esperado da rota.

◎

Objetivo do classificador

Usar métricas relativas para estimar se o fluxo está em estado OK, RISCO ou FALHA, oferecendo apoio ao monitoramento, não substituindo a análise operacional.

Ideia central: o modelo deve aprender padrões de degradação, e não simplesmente memorizar qual rota costuma ter RTT maior. Por isso, identificadores de rota, país e IP não devem ser usados como variáveis preditoras se o objetivo é generalizar para rotas diferentes.
02 · Modelos avaliados

Três abordagens para a mesma tarefa

Todos os modelos resolvem um problema de classificação, mas aprendem de maneiras diferentes. A escolha deve considerar desempenho, estabilidade, custo e facilidade de explicar as decisões.

Modelo individual
⑂

Árvore de Decisão

Aprende regras hierárquicas do tipo “se esta métrica ultrapassa um limite, siga para este ramo”. Cada caminho da raiz até uma folha corresponde a uma decisão.

Vantagens: rápida, interpretável e simples de visualizar. Limitações: pode sobreajustar se crescer demais e ser sensível a pequenas mudanças nos dados.

Ensemble · Bagging
▥

Random Forest

Treina várias árvores com amostras e subconjuntos de atributos diferentes. A previsão final combina as saídas das árvores, normalmente por votação na classificação.

Árvore 1

Vantagens: reduz a variância e costuma ser mais estável que uma árvore única. Limitações: consome mais memória e é menos transparente para explicar uma previsão individual.

Ensemble · Boosting
⇧

XGBoost

Constrói árvores sequencialmente; cada etapa procura melhorar o conjunto atual, reduzindo uma função de perda com regularização e controle da taxa de aprendizado.

Árvore 1+Árvore 2+Árvore 3→Modelo

Vantagens: alto desempenho em dados tabulares e opções de regularização. Limitações: exige ajuste cuidadoso e pode ser mais complexo de interpretar e reproduzir.

Bagging × Boosting

Bagging treina estimadores em paralelo e agrega suas previsões para reduzir variância. Boosting adiciona estimadores em sequência, procurando corrigir erros do conjunto atual.

Hiperparâmetros importam

Profundidade, quantidade de árvores, tamanho mínimo das folhas, taxa de aprendizado e regularização controlam a complexidade. O ajuste deve ocorrer somente nos dados de treino, sem usar o conjunto final de teste.

03 · Metodologia

Como a comparação deve ser conduzida

Uma comparação justa mantém o mesmo conjunto de dados, as mesmas variáveis de entrada, a mesma separação temporal e a mesma métrica principal para os três algoritmos.

Preparar a baseline

Usar o Período A como janela histórica de referência, calculando estatísticas robustas por rota.

Gerar atributos relativos

Transformar medições do Período B em variáveis que descrevem o desvio em relação à baseline.

Separar por tempo

Manter a ordem temporal entre treino, validação e teste, evitando que observações futuras influenciem o passado.

Ajustar e avaliar

Ajustar hiperparâmetros no treino/validação e reservar o teste para uma avaliação final independente.

Nota de rigor metodológico: a versão do artigo informa GridSearchCV(cv=3). Para dados temporais, o cv=3 padrão não garante validação temporal. A validação cruzada deve ser configurada para respeitar a ordem cronológica (por exemplo, TimeSeriesSplit, quando apropriado) ou substituída por janelas temporais explícitas. Antes de tratar os resultados como definitivos, também é necessário confirmar que não há atributos calculados com informação futura e que a mesma amostra não aparece em treino e avaliação.

04 · Reprodutibilidade

Exemplo de pipeline em Python

O trecho abaixo é um exemplo didático de avaliação com divisão temporal. Os nomes das colunas devem ser ajustados ao conjunto de dados real; ele não substitui a execução e a validação do notebook do projeto.

Python · exemplo de avaliação temporal
import pandas as pd
from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import classification_report, confusion_matrix, f1_score

# O DataFrame deve estar ordenado cronologicamente antes do corte.
df = pd.read_csv("data/processed/dataset_rotulado.csv")
df = df.sort_values("timestamp").reset_index(drop=True)

# Exclua identificadores e qualquer coluna que revele a resposta.
colunas_excluidas = ["timestamp", "label", "pais", "ip", "rota"]
X = df.drop(columns=[c for c in colunas_excluidas if c in df.columns])
y = df["label"]

# Exemplo simples de corte temporal: primeiros 70% para treino,
# últimos 30% para avaliação. Ajuste os limites ao protocolo do projeto.
corte = int(len(df) * 0.70)
X_treino, X_teste = X.iloc[:corte], X.iloc[corte:]
y_treino, y_teste = y.iloc[:corte], y.iloc[corte:]

modelo = DecisionTreeClassifier(random_state=42)
grade = {"max_depth": [3, 5, 7, 10], "min_samples_leaf": [1, 5, 10]}

# A validação temporal ocorre apenas dentro do bloco de treino.
cv_temporal = TimeSeriesSplit(n_splits=3)
busca = GridSearchCV(
    modelo, grade, cv=cv_temporal,
    scoring="f1_macro", n_jobs=-1
)
busca.fit(X_treino, y_treino)

# O bloco de teste é usado apenas depois do ajuste.
pred = busca.best_estimator_.predict(X_teste)
print("Melhores parâmetros:", busca.best_params_)
print("F1 macro:", f1_score(y_teste, pred, average="macro"))
print(classification_report(y_teste, pred, zero_division=0))
print(confusion_matrix(y_teste, pred))
Python · comparação de métricas
from time import perf_counter
from sklearn.metrics import f1_score, precision_score, recall_score

def avaliar_modelo(nome, modelo, X_treino, y_treino, X_avaliacao, y_avaliacao):
    inicio = perf_counter()
    modelo.fit(X_treino, y_treino)
    tempo_treino = perf_counter() - inicio

    inicio = perf_counter()
    previsoes = modelo.predict(X_avaliacao)
    tempo_predicao = perf_counter() - inicio

    return {
        "modelo": nome,
        "precision_macro": precision_score(
            y_avaliacao, previsoes, average="macro", zero_division=0
        ),
        "recall_macro": recall_score(
            y_avaliacao, previsoes, average="macro", zero_division=0
        ),
        "f1_macro": f1_score(
            y_avaliacao, previsoes, average="macro", zero_division=0
        ),
        "tempo_treino_s": round(tempo_treino, 4),
        "tempo_predicao_s": round(tempo_predicao, 4),
    }

06 · Conclusão

O melhor modelo é o que entrega desempenho confiável com custo adequado

Com base exclusivamente nos resultados reportados, a Árvore de Decisão é a recomendação preliminar: ela alcança F1 Macro de 1,0000, assim como o XGBoost, e apresenta os menores tempos de treinamento e predição. Além disso, suas regras são mais fáceis de explicar para uma equipe que precisa entender por que um fluxo foi classificado como OK, RISCO ou FALHA.

Essa recomendação ainda não deve ser considerada definitiva. A pontuação perfeita exige uma auditoria de vazamento de dados e uma nova avaliação que respeite a ordem temporal. Se o desempenho permanecer alto em um teste futuro, separado e independente, a árvore poderá ser defendida como a solução mais simples e eficiente para o cenário estudado.

A Random Forest continua sendo uma alternativa quando a estabilidade entre árvores for importante; o XGBoost merece ser escolhido se uma avaliação rigorosa demonstrar uma melhoria que compense seu custo e sua maior complexidade.

Limitações do estudo

  • Os resultados precisam ser reproduzidos a partir dos arquivos e do notebook final.
  • É necessário documentar as classes e apresentar precision, recall, F1 por classe e matriz de confusão.
  • O desempenho pode mudar com novas rotas, períodos ou padrões de tráfego.
  • O tempo medido depende do hardware, da versão das bibliotecas e do tamanho do lote.

Próximas etapas

  • Validar o corte temporal e verificar vazamento entre baseline, atributos e rótulos.
  • Executar novamente os três modelos com protocolo idêntico.
  • Salvar parâmetros, versões, métricas e matriz de confusão em artefatos reproduzíveis.
  • Testar em um intervalo futuro e monitorar data drift após a implantação.
